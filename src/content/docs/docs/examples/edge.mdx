This example demonstrates reactive state in a Cloudflare Durable Object, with one object identity per IP. It allows the first 100 requests in a window and logs the first request that exceeds that limit.

**This is an in-memory demonstration.** An object can handle several requests while resident, but Cloudflare can discard its memory on hibernation, eviction, or restart. This example then starts a fresh counter and window. A production rate limiter that must enforce a window across restarts needs persistent storage; that is a different lifecycle contract. See [Durable Object lifecycle](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/).

The Worker entry and Durable Object request method use ordinary JavaScript. Lexical Para signals live inside the constructor, where the request callback closes over them; `signal` is not used as a class-field modifier.

## src/limiter.pjs

```pjs
import { effect as observe, untrack } from "@lyku/para-signals";

export class RateLimiter {
  constructor(state) {
    signal count = 0;
    signal windowStart = Date.now();
    derived overLimit = count > 100;

    let wasOverLimit = false;
    observe(() => {
      const isOverLimit = overLimit;
      if (isOverLimit && !wasOverLimit) {
        untrack(() => {
          console.log(`rate limit crossed: ${count} requests in window`);
          // First crossing: rate limit crossed: 101 requests in window
        });
      }
      wasOverLimit = isOverLimit;
    });

    this.check = () => {
      if (Date.now() - windowStart > 60_000) {
        count = 0;
        windowStart = Date.now();
      }
      count++;

      return Response.json({
        allowed: !overLimit,
        remaining: Math.max(0, 100 - count),
      });
    };
  }

  async fetch(req) {
    return this.check();
  }
}
```

### What's reactive and what isn't

- `count` and `windowStart` belong to each resident object instance. The window resets on the first request more than 60 seconds after its start, rather than on a background timer.
- `overLimit` is a lazy derived signal. Requests 1–100 are allowed; request 101 is rejected and logs the crossing. Further requests remain rejected without repeating the log until a new window begins.
- `observe` aliases the published core `effect` API. `wasOverLimit` detects the false-to-true transition. `untrack` reads the count for logging without adding another dependency. This avoids the `when` helper that is bundled with Parabun but absent from npm `@lyku/para-signals@0.0.1-pre.4`.
- The effect has the same lifetime as the instance and owns no timer or external resource. Storage is deliberately not added here; recreating the instance resets its state.

## The Worker entry that calls it

The `fetch` handler that proxies requests through the Durable Object is plain Workers code; nothing reactive happens here, so it's plain JavaScript:

```pjs
// src/index.pjs — Wrangler needs this named class export.
export { RateLimiter } from "./limiter.pjs";

export default {
  async fetch(req, env) {
    const ip = req.headers.get("cf-connecting-ip") ?? "unknown";
    const stub = env.RATE_LIMIT.get(env.RATE_LIMIT.idFromName(ip));
    const { allowed, remaining } = await (await stub.fetch("https://internal/check")).json();

    if (!allowed) {
      return new Response("rate limited", {
        status: 429,
        headers: { "Cache-Control": "no-store", "Retry-After": "60" },
      });
    }
    return Response.json({ ok: true, remaining }, {
      headers: { "X-RateLimit-Remaining": String(remaining),
        "Cache-Control": "no-store" },
    });
  },
};
```

```jsonc
    "bindings": [{ "name": "RATE_LIMIT", "class_name": "RateLimiter" }]
  },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["RateLimiter"] }]
}
```

This configuration creates a new SQLite-backed namespace. The example makes no storage writes, so its counters still reset when the instance is recreated. For an existing deployment, preserve its migration history.

`--target browser` is correct for Workers — the V8 isolate runtime has web-platform globals but no Node APIs.

## Build and run locally

```bash
parabun install
parabun run dev
```

Use `curl http://localhost:8787` to exercise the local Worker. On a fresh object, the first response has `remaining: 99`; request 100 has `remaining: 0`; request 101 returns HTTP 429. For production publication, `parabun run deploy` is a separate step requiring your Cloudflare account.

The Parabun build bundles the published signals package into standard JavaScript. The entry exports both the Worker handler and `RateLimiter`, matching the Wrangler binding. The HTTP responses use `no-store` because the allowance depends on the caller and current window.
